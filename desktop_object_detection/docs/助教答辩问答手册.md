# P05 桌面目标检测：助教答辩问答手册

> 本手册中的模型、参数和指标均对应当前实际交付版本：`models/expanded_v1/best.pt`。  
> 建议先掌握“30 秒介绍”和“核心数字”，再按专题练习问答。

## 一、30 秒标准介绍

本项目采用 Ultralytics YOLO11n 单阶段目标检测模型，对鼠标、键盘、笔记本电脑、杯子和头戴式耳机五类桌面物体进行实时检测。模型由旧版 P05 权重继续迁移学习，在 5,000 张扩充数据上微调 30 个 epoch，训练集、验证集和测试集分别为 3,947、376 和 677 张。当前模型约有 259 万个参数，计算量约 6.5 GFLOPs，兼顾检测精度和实时速度。独立测试集上的 Precision 为 0.785、Recall 为 0.728、mAP50 为 0.806、mAP50-95 为 0.525。摄像头端使用 640 像素输入、0.5 置信度阈值和 0.45 NMS IoU 阈值。

## 三、模型基础问题

### 1. 你用的是什么模型？

使用的是 **Ultralytics YOLO11n** 目标检测模型，`n` 表示 nano，即 YOLO11 系列中体积较小、速度较快的版本。我们针对五类桌面物体进行了迁移学习。

### 2. 为什么选择 YOLO11n？

实验需要摄像头实时检测，还计划部署到 Jetson，因此需要在精度、参数量和速度之间折中。YOLO11n 只有约 259 万参数和约 6.5 GFLOPs，比大模型更适合实时运行；如果只追求精度，可以换用 YOLO11s 或 YOLO11m，但延迟和硬件压力会增加。

### 3. YOLO 是分类模型还是检测模型？

是目标检测模型。图像分类只回答“整张图里是什么”，目标检测还要输出每个物体的类别、置信度和边界框位置，因此可以在一张图中同时识别多个物体。

### 4. 什么叫单阶段目标检测？

单阶段模型一次前向传播就直接预测类别和边界框。Faster R-CNN 等两阶段模型会先提出候选区域，再进行分类和回归。单阶段通常速度更快，更适合实时摄像头。

### 5. YOLO11n 的结构大致是什么？

可以分成三部分：

1. Backbone 提取由浅到深的图像特征，当前网络包含 Conv 和 C3k2 等模块。
2. Neck 通过上采样、拼接和多尺度融合，把细节信息与高层语义结合；SPPF 扩大感受野，C2PSA 加强重要区域的信息建模。
3. Detect Head 在多个尺度上预测类别和边界框，兼顾大小不同的目标。

答辩时不必逐层背网络，只要能解释“特征提取—多尺度融合—检测输出”即可。

### 6. 为什么要多尺度检测？

摄像头中物体大小会随距离变化。高分辨率特征层更适合小目标，低分辨率深层特征更适合较大目标。融合多个尺度可以提高远距离鼠标、小杯子等目标的检出能力。

### 7. 模型是 anchor-based 还是 anchor-free？

YOLO11 检测头采用 anchor-free 思路，不依赖预先手工设置的一组固定锚框，并结合分布式边界框回归（DFL）估计框的位置。

### 8. 模型最终输出什么？

每个保留目标输出类别 ID、类别名、置信度，以及 `x1, y1, x2, y2` 像素边界框。程序把结果画到画面上，同时写入逐帧 CSV 日志。

### 9. `best.pt` 是什么？为什么不用 `last.pt`？

`.pt` 是 PyTorch 权重文件。`best.pt` 是训练过程中验证指标最好的检查点；`last.pt` 是最后一个 epoch 的权重。最后一轮不一定泛化最好，所以部署时使用 `best.pt`。

### 10. 这个模型是从零训练的吗？

不是。从旧版 P05 的 `models/best.pt` 继续微调，属于迁移学习。旧权重本身源自 YOLO11n，因此模型已经具备通用视觉特征和 P05 初始类别知识，再通过扩充数据改善覆盖范围。

## 四、数据集与标注问题

### 11. 一共用了多少数据？

共 5,000 张图、7,813 个目标框。划分为训练集 3,947 张、验证集 376 张、测试集 677 张。

### 12. 数据从哪里来？

包括 500 张冻结的 P05 基线混合数据，以及 4,500 张 Open Images V7 公开真实图片。Open Images 保留了官方 train、validation、test 边界，并记录了来源 ID 和 URL。

### 13. 是否全部都是自己拍摄的？

不是，不能这样回答。P05 基线为混合来源，其中还保留了可追溯的生成图；扩充部分是 Open Images V7 公开真实图。项目的重点是目标检测流程和模型实验，不应把公开或生成数据表述成全部自采。

### 14. 五个类别如何编号？

`0 mouse`、`1 keyboard`、`2 laptop`、`3 cup`、`4 headphones`。训练、测试和部署必须保持相同顺序。

### 15. `MIX` 和 `NEG` 是模型类别吗？

不是。它们只是 P05 文件名中的场景码。`MIX` 表示图中有两个及以上目标框，`NEG` 表示负样本。模型真正训练的类别只有五类。

### 16. 标注格式是什么？

使用 YOLO TXT，每行是：

```text
class_id x_center y_center width height
```

后四个值都除以原图宽高，归一化到 `[0,1]`。

### 17. 打开的笔记本为什么可能有两个框？

因为笔记本本体标为 `laptop`，清晰可见的内置键盘还要单独标为 `keyboard`。两个框允许嵌套，这是项目已经锁定的标注规则。

### 18. 遮挡物体怎样标框？

只框实际可见部分，不推测被遮挡区域；边界框不包含阴影和倒影。这样能保持标注规则一致。

### 19. 为什么需要负样本？

负样本能教模型“哪些东西不是目标”，降低把显示器、遥控器、触控板、瓶子、碗或入耳式耳机误判成五类目标的概率。负样本对应空 TXT。

### 20. 类别数量是否平衡？

不是完全相等。目标框数量分别是：mouse 965、keyboard 1,720、laptop 2,238、cup 1,739、headphones 1,151。类别不均衡可能导致模型更偏向样本多、场景容易的类别，因此评估时必须查看逐类指标，不能只看总体 mAP。

### 21. 如何避免训练集和测试集泄漏？

公开图保留 Open Images 官方划分；工程检查了完全重复文件、重复来源 ID，以及跨划分 dHash 距离不大于 1 的近重复候选，目前没有发现这些重复。但官方 test 仍与官方 train 属于同一数据体系，因此它属于“同源未见图片”，不是完全跨域盲测。

### 22. 公开数据标签是否全部人工复核？

没有。公开框经过自动格式检查、完整性检查、重复检查和抽样可视检查，但尚未逐图人工复标。因此工程实验可以使用这些指标，但不能把它描述成经过双人复核的研究级 ground truth。

## 五、训练过程问题

### 23. 训练参数是什么？

当前扩充模型训练 30 个 epoch，batch size 16，训练输入尺寸 512，设备为 Apple MPS，workers 为 4，随机种子为 0，启用了确定性设置，early-stopping patience 为 10。

### 24. 为什么训练是 512，摄像头却使用 640？

YOLO 是全卷积检测器，可接受不同的合法输入尺寸。训练使用 512 是为了减少训练时间和显存压力；推理使用 640 能保留更多细节，对较小目标可能更友好，但计算量也会增加。最严谨的性能比较应固定相同输入尺寸；本项目独立测试使用 640，与部署设置一致。

### 25. 使用了哪些数据增强？

训练时使用小角度旋转 `5°`、平移 `0.1`、缩放 `0.3`、水平翻转 `0.5`、有限 Mosaic `0.5`，最后 10 个 epoch 关闭 Mosaic；MixUp 为 0。训练时的数据增强是临时变换，不会冒充新的原始采集照片。

### 26. 为什么使用数据增强？

增强让模型看到位置、尺度、方向和背景组合的变化，降低只记住固定拍摄方式的风险。但增强不能代替真实跨设备、跨场地数据，尤其不能完全模拟手持遮挡、特殊材质和真实曝光变化。

### 27. 使用了什么优化器和学习率？

训练记录中优化器为 `auto`，由 Ultralytics 根据模型和训练设置自动选择；记录的初始学习率参数为 0.01、动量 0.937、权重衰减 0.0005，并有 3 个 warmup epoch。回答时以训练保存的 `args.yaml` 为准。

### 28. 训练损失包括什么？

主要包括：

- Box loss：约束预测框的位置和真实框接近。
- Classification loss：约束类别预测正确。
- DFL loss：让边界位置的分布回归更精细。

损失越小通常越好，但最终仍应以独立验证和测试指标判断泛化，而不是只看训练损失。

### 29. 为什么训练 30 个 epoch？

这是本轮扩充实验设定的预算。模型在 30 轮内已经收敛，epoch 27 的验证集 mAP50-95 达到本次最高值 0.5877。继续训练不一定提高泛化，反而可能过拟合；是否增加轮数应由验证曲线决定。

### 30. 什么是过拟合？你们有没有过拟合？

过拟合是训练集表现很好，但未见数据表现明显下降。当前模型在独立 test 上仍有 mAP50 0.806，并且 Open Images 官方 test 子集有 mAP50 0.775，说明不是简单记忆训练图片；但完全跨摄像头、跨地点的盲测尚未完成，所以不能宣称已经彻底解决过拟合或域偏移。

## 六、指标与实验结果问题

### 31. Precision 是什么？

在模型报出的检测结果中，真正正确的比例：

```text
Precision = TP / (TP + FP)
```

Precision 低表示误检较多。

### 32. Recall 是什么？

在所有真实目标中，被模型成功找到的比例：

```text
Recall = TP / (TP + FN)
```

Recall 低表示漏检较多。

### 33. IoU 是什么？

IoU 是预测框与真实框交集面积除以并集面积，用来衡量两个框的重合程度。IoU 越接近 1，定位越准确。

### 34. AP 和 mAP 是什么？

AP 是某一类别在不同置信度阈值下 Precision-Recall 曲线的面积；mAP 是多个类别 AP 的平均。mAP50 使用 IoU=0.5 判断匹配，mAP50-95 会在 0.5 到 0.95 的多个 IoU 阈值上平均，因此更严格、更能反映定位精度。

### 35. 当前新模型的总体指标是多少？

在 677 张独立 test 上：Precision 0.785、Recall 0.728、mAP50 0.806、mAP50-95 0.525。

### 36. 新模型相对旧模型提升多少？

同一独立 test 上：

| 指标 | 旧模型 | 新模型 | 提升 |
| --- | ---: | ---: | ---: |
| Precision | 0.531 | 0.785 | +0.254 |
| Recall | 0.384 | 0.728 | +0.344 |
| mAP50 | 0.385 | 0.806 | +0.421 |
| mAP50-95 | 0.197 | 0.525 | +0.328 |

### 37. 鼠标类别现在表现如何？

总体 test 中鼠标 mAP50 为 0.849、Recall 为 0.847；微调前分别为 0.464 和 0.547。Open Images 官方 test 子集的鼠标 mAP50 为 0.826、mAP50-95 为 0.586。鼠标已有明显提升，但白色手持、手部遮挡等部署场景仍需要专项数据。

### 38. 当前最弱的类别是什么？

在 Open Images 官方 test 子集上，`headphones` 最弱，mAP50 为 0.657、mAP50-95 为 0.332。可能原因包括外形差异大、姿态变化大、部分遮挡，以及与入耳式耳机等困难负样本的视觉混淆。

### 39. 为什么 mAP 很高，现场仍可能漏检？

mAP 是整个测试集的平均指标，而现场可能属于训练数据覆盖不足的特殊子域，例如白色鼠标、手持姿态、近距离透视、人物衣服背景、强遮挡或曝光变化。平均指标不能保证每一种场景都稳定，这属于域偏移问题。

### 40. 模型的完全未见数据泛化能力如何？

可以确认具有较好的“未参与本次微调的同源图片”泛化：624 张 Open Images 官方 test 上 mAP50 为 0.775、mAP50-95 为 0.511。但这不是完全跨域证明，因为 train 和 test 仍来自同一公开数据体系。严格结论应是“同源未见泛化已验证，跨设备、跨场地盲测仍待验证”。

## 七、实时检测程序问题

### 41. 摄像头程序的处理流程是什么？

OpenCV 打开摄像头并逐帧读取图像，Ultralytics YOLO 完成预处理、前向推理和后处理，NMS 去除重复框，程序再绘制类别、置信度、边界框和 FPS，并把逐框结果保存到 CSV。按 `s` 保存截图，按 `q` 或 `Esc` 退出。

### 42. 什么是置信度阈值？为什么设为 0.5？

置信度阈值决定低于多少分的预测被丢弃。当前为 0.5，是误检与漏检之间的折中。提高阈值通常减少误检但增加漏检；降低阈值通常提高召回但可能产生更多误检。它是部署参数，不需要重新训练就能调整。

### 43. 什么是 NMS？为什么 IoU 阈值是 0.45？

同一目标可能产生多个重叠候选框。NMS 会保留置信度最高的框，并抑制与它高度重叠的重复框。当前 NMS IoU 阈值为 0.45；阈值太低可能误删相互靠近的不同物体，太高则可能留下重复框。

### 44. 摄像头使用什么设备加速？

当前 Mac 入口指定 `mps`，即使用 Apple Silicon GPU 的 Metal Performance Shaders。配置还允许自动选择设备；迁移到 NVIDIA/Jetson 时通常使用 CUDA，并需要匹配 JetPack、CUDA 和 PyTorch 版本。

### 45. 实时 FPS 是多少？

摄像头演示画面曾显示约 40 FPS，但 FPS 会受分辨率、摄像头、显示、日志写入、模型格式和硬件影响。此前 58.31 FPS 是本机另一轮 benchmark 记录，不能冒充当前 Jetson 实测。Jetson 性能必须在目标设备上重新测量。

### 46. 为什么实时 FPS 会波动？

摄像头采集、图像预处理、首次模型预热、GPU 调度、后处理、窗口绘制和磁盘日志都会造成波动。程序显示的是指数平滑 FPS，比单帧瞬时值稳定。

### 47. 如果同一个画面出现多个目标怎么办？

模型会对每个目标分别输出边界框和类别。只要置信度达到阈值且没有被 NMS 错误抑制，就可以同时识别多个类别和同类多个实例。

### 48. 为什么有时框会抖动？

当前程序是逐帧独立检测，没有使用目标跟踪或跨帧平滑。相邻帧的图像噪声和预测轻微变化会导致边界框抖动。可通过 ByteTrack、滑动平均或卡尔曼滤波改善稳定性，但会增加系统复杂度。

### 49. 当前程序保存什么结果？

实时窗口显示标框画面；每次运行会在 `outputs/logs/` 保存逐框 CSV。按 `s` 可把标框截图保存到 `outputs/images/`；开启 `save_video` 后可在 `outputs/videos/` 保存视频。

## 八、局限、改进和反问问题

### 50. 当前项目最大的局限是什么？

主要有四点：

1. Open Images 标签尚未逐图人工复核。
2. P05 基线是混合来源，并非全部真实自采。
3. 缺少新摄像头、新场地、新物体实例组成的严格盲测集。
4. 头戴式耳机和强遮挡、手持鼠标等困难场景仍是薄弱点。

### 51. 下一步如何提高泛化？

优先收集真实部署失败案例，而不是盲目增加同分布图片：补充不同品牌和颜色的鼠标、手持与遮挡姿态、新桌面背景、逆光和弱光、画面边缘目标以及困难负样本；冻结一套不参与调参的盲测集；随后再做小学习率微调并逐类比较指标。

### 52. 为什么不直接换更大的模型？

更大的模型可能提高容量，但不一定解决数据域偏移。如果白色手持鼠标在训练集中缺失，换大模型也可能失败。应先补充针对性数据和检查标签，再评估是否从 YOLO11n 升级到 YOLO11s。

### 53. 如何降低误检？

补充困难负样本、检查错标和漏标、适当提高置信度阈值，并分析混淆矩阵。不能只靠把阈值调得很高，因为这会牺牲 Recall。

### 54. 如何降低漏检？

补充对应姿态和尺度的数据、检查漏标、适当降低置信度阈值、提高推理分辨率，或使用容量更大的模型。同时要观察误检是否同步增加。

### 55. 如果助教要求证明程序不是只会跑一个图片怎么办？

现场依次展示：单目标、两类同框、五类同框、遮挡目标和困难负样本；移动目标并改变距离，说明程序逐帧实时输出。再打开检测日志 CSV，证明结果不仅画在窗口上，还被结构化记录。

### 56. 如果助教问“你的创新点是什么”怎么回答？

不要把 YOLO11 本身说成自己的算法创新。可以回答工程贡献：建立五类桌面物体的统一标注规则；组合 P05 与公开数据并进行来源、重复和划分管理；实现训练、评估、错误分析、摄像头实时检测和 ROS2/Jetson 部署接口；通过同一测试集的新旧模型对比量化改进。

### 57. 如果助教问“这个结果可信可靠吗”怎么回答？

回答应分层：独立 test 与新旧同集对比是可复现的，格式和重复检查已通过；但公开标签未全量人工复核，Open Images test 也不是跨域盲测，Jetson 尚需实机测试。因此当前证据足以支持课程工程实验，但仍有明确的研究级和部署级验证边界。

## 九、汇报时最容易说错的内容

以下说法不要使用：

| 错误说法 | 正确说法 |
| --- | --- |
| “我用的是 YOLOv11” | 使用 Ultralytics YOLO11n；官方名称写 YOLO11，不加字母 v |
| “模型是从零训练的” | 从旧 P05 `best.pt` 继续迁移学习 |
| “训练图片全部是自己拍的” | 500 张 P05 基线混合数据 + 4,500 张 Open Images V7 |
| “训练和推理都是 640” | 本轮训练 512，独立测试和摄像头推理 640 |
| “准确率是 80.6%” | 更准确地说独立 test 的 mAP50 是 0.806；它不等于普通分类准确率 |
| “测试集证明了所有场景都能识别” | 证明同源未见图片表现，完全跨域仍需盲测 |
| “40 FPS 就是 Jetson 速度” | 这是当前 Mac 演示环境结果，Jetson 必须实测 |
| “MIX 和 NEG 是第六、第七类” | 它们是文件场景码，模型只有五类 |
| “生成图也是真实照片” | 基线含可追溯生成数据，必须如实披露 |
| “框越多说明效果越好” | 框必须对应真实目标；多框也可能是误检或重复框 |

## 十、建议的三分钟现场演示顺序

1. 用 30 秒标准介绍说明任务、模型、类别和核心指标。
2. 双击 `启动摄像头检测.command`，先展示键盘或杯子等稳定类别。
3. 加入鼠标和笔记本，展示多目标同时检测。
4. 改变距离、角度和部分遮挡，主动说明域偏移和当前边界。
5. 展示空桌或非目标物，观察困难负样本误检情况。
6. 按 `s` 保存截图，退出后展示 `outputs/logs/` 中的 CSV。
7. 最后用新旧模型指标表说明扩充训练带来的量化提升。
