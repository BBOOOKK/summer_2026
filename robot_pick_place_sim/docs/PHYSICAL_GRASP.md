# 物理抓取链路

## 改造原因

旧版 `object_manager` 在夹取后以 20 Hz 连续调用 Gazebo `SetEntityState`，将方块位姿设置为末端位姿。这可以验证任务状态机，但不能证明夹爪真的接触到目标，也会掩盖底座滑动、工具姿态错误和桌面碰撞。

## 当前链路

1. `object_manager` 每轮只在 `VALIDATING` 阶段将方块复位到 A，运输期间不写位姿。
2. 左右夹指均是受 `gripper_controller` 控制的对称移动关节。
3. 方块接触传感器以 100 Hz 发布 `/gazebo/contacts/target`。
4. `robot_grasp_joint` 仅在目标距离合法且左右夹指都存在近期接触时，在 `mecharm270::tool0` 与 `target_object::object` 之间创建 Gazebo `fixed joint`。
5. 到达 B 后先拆除物理关节，再张开夹爪；方块在重力下落到桌面。
6. `object_trajectory_<run_id>.csv` 以 50 Hz 独立记录方块的世界位姿和线速度。

## 首次端到端 smoke

2026-09-01 会话 `20260901_045423_264569` 完成了首次物理链路全流程：

- 双指接触通过，物理关节成功附着和拆卸各 1 次；
- 运输期间 `SetEntityState` 写入 0 次；
- 方块最终世界位置约为 `[0.2111, -0.1685, 0.7695]` m，位于 B 区内；
- 完整动作用时约 19.56 s。

这是开发 smoke，不是最终 5 轮验收。最终验收还必须同时通过运行时碰撞监控、接触源健康、安全锁存和自动日志分析。

## 边界

可拆固定关节比位姿跟随更接近物理抓取，但仍是工程化仿真简化，不等价于真实指尖摩擦、夹持力或材料变形认证。
